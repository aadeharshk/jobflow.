# Free Tier vs Paid: What Each Feature Needs

> Limits and prices are from the `cloudflare/cloudflare-docs` repository (commit dated 2026-11-26). See [`../research/cloudflare-references.md`](../research/cloudflare-references.md) Appendix A and the scenario model in [`cloudflare-cost-analysis.md`](cloudflare-cost-analysis.md). Re-verify on Cloudflare's live pricing pages before budgeting.

**Policy (owner-approved):** security and architecture are never weakened to fit the free tier. Where a feature needs a paid service, it is marked below.

## Phase 3 (this release)

| Feature                           | Cloudflare services           | Workers Free                                                                                                                    | Needs paid?                                                                                                                      |
| --------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| SPA hosting                       | Workers Static Assets         | Unlimited, free asset requests                                                                                                  | No                                                                                                                               |
| API, auth, sessions               | Workers + D1                  | 100k requests/day; **10 ms CPU per invocation**; D1 5M rows read and 100k rows written per day, 5 GB total, 500 MB per database | No for low traffic. Phase 3 routes are I/O-bound; CPU per request has not been measured on production (to do after first deploy) |
| Résumé storage                    | R2                            | 10 GB-month, 1M Class A / 10M Class B ops per month                                                                             | No (≈2,000 users × 5 MB)                                                                                                         |
| Outbound governor, source limiter | Durable Objects (SQLite)      | 100k requests/day, 13,000 GB-s/day, 5 GB                                                                                        | No                                                                                                                               |
| Background queues                 | Queues                        | 10,000 ops/day (≈3,300 messages), 24 h retention                                                                                | No in Phase 3 (no producers active yet)                                                                                          |
| Cron Triggers                     | Workers                       | 5 per account (JobFlow uses 2)                                                                                                  | No                                                                                                                               |
| Rate limiting                     | Workers Rate Limiting binding | Availability per plan **not verified in-session**                                                                               | Check on the first deploy; the app degrades gracefully if the binding is absent                                                  |
| Observability                     | Workers Logs                  | Plan limits apply                                                                                                               | Optional                                                                                                                         |

**Conclusion:** Phase 3 can run on the **Workers Free** plan for evaluation. Production is recommended on **Workers Paid ($5/month)** for the 5-minute CPU limit, 1M queue ops/month, longer queue retention and headroom.

## Not used (prohibited core infrastructure)

Supabase, Firebase, Vercel, AWS, Railway, Render and any external database are not used. Google is used only for OAuth (and later the Gmail API, as an integration).
